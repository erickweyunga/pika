# Pika Language Specification - v0 (draft)

Status: draft for discussion. Nothing here is frozen until the v0 compiler passes its conformance tests.

Pika is a general-purpose, statically typed, compiled programming language. Its syntax is command-oriented (`:commands`, `$variables`, `[command substitution]`, `key=value` arguments, `do={}` blocks), and it pairs that syntax with the *semantics* of a modern systems language: value types, ownership without a garbage collector, structs and traits, generics, and native code generation.

---

## 1. Design goals

1. **Readable, command-shaped syntax.** Every statement is a command. The same shape is used for built-ins, user functions, methods and module functions.
2. **Static types with local inference.** Function signatures are always explicit. Types inside function bodies are inferred.
3. **No garbage collector.** Memory is managed by ownership and deterministic destruction. There are no user-visible reference types and no lifetime annotations in v0.
4. **Fast by default.** Ahead-of-time compilation to native code. Generics are monomorphized.
5. **Safe by default.** No null, no implicit numeric conversion, no uninitialized reads, no data races (v0 is single-threaded), checked arithmetic and bounds. Unsafe operations are confined to `:unsafe` blocks.
6. **One obvious way.** Where two spellings would do, Pika keeps one canonical form and the formatter enforces it.

### Non-goals for v0

Concurrency, dynamic dispatch (trait objects), user-defined reference types, GPU/SIMD, macros, Python interop, and incremental compilation. Syntax for some of these is reserved (section 15).

## 2. A taste

```pika
:use /std/math
:use /std/strings

:struct Point impl=Copy,Eq,Display {
    x:f64
    y:f64

    :fn new x:f64 y:f64 -> Self do={
        :return Self{x=$x; y=$y}
    }

    :fn dist self other:Point -> f64 do={
        :const dx ($self->x - $other->x)
        :const dy ($self->y - $other->y)
        :return [/math/sqrt (($dx * $dx) + ($dy * $dy))]
    }
}

:enum Shape {
    circle center:Point radius:f64
    rect min:Point max:Point
}

:fn area shape:Shape -> f64 do={
    :match $shape {
        Shape->circle _ r do={ :return (/math/pi * $r * $r) }
        Shape->rect a b do={ :return (($b->x - $a->x) * ($b->y - $a->y)) }
    }
}

:fn parse_port s:String -> u16 raises do={
    :const n [/strings/parse_int? $s]
    :if (($n < 1) or ($n > 65535)) do={
        :error "port out of range: $n"
    }
    :return ($n as u16)
}

:fn main do={
    :const shapes {
        [Shape->circle [Point->new 0.0 0.0] 2.0]
        [Shape->rect min=[Point->new 0.0 0.0] max=[Point->new 3.0 4.0]]
    }
    :foreach i,s in=$shapes do={
        :put "shape $i has area $([:area $s])"
    }

    :onerror e in={
        :put "port = $([:parse_port? "8080"])"
        :put "port = $([:parse_port? "99999"])"
    } do={
        :put "failed: $e"
    }

    :for i from=1 to=3 do={ :put $i }
}
```

## 3. Lexical structure

### 3.1 Source text

- Source files are UTF-8 and use the extension `.pk`.
- Line endings may be LF, CRLF or CR. They are normalized to LF before lexing.

### 3.2 Comments

- `#` starts a comment that runs to the end of the physical line.
- `##` starts a documentation comment attached to the following declaration.
- There are no block comments.
- `#` inside a string literal is not a comment.

### 3.3 Whitespace and the "joined" rule

Each token records whether it was **joined** to the previous token (no whitespace or comment between them). The parser uses this flag in the following places, and nowhere else:

| Construct | Rule | Example |
|---|---|---|
| Command head | `:` must be joined to the following identifier and must **not** be joined to a preceding identifier | `:put`, `[:len $s]` |
| Type annotation | `:` must be joined to the preceding name and to the type | `x:i64` |
| Named argument | `name=value`: no whitespace on either side of `=` | `from=1`, `do={...}` |
| Path | `/` segments must be joined | `/std/math/sqrt` |
| Generic arguments | `<` must be joined to the preceding name; a `<` joined to a name always starts type arguments, so a comparison after a field or method name needs spaces: `($a->len < 3)` | `List<i64>`, `:parse<i64>`, `$p->map<f64>` |
| Struct and typed collection literals | `{` must be joined to the type | `Point{x=1.0; y=2.0}`, `List<i64>{}` |
| Option types | `?` must be joined to the type | `i64?` |
| Calls that can raise | `?` must be joined to the head of the command, after its type arguments | `[/fs/read? $path]`, `[$s->parse_int?]` |
| Member access | `->` must be joined to the value or type before it | `$p->x`, `Color->red` |
| Negative literals in arguments | `-` must be joined to the number | `:put -5` |

Generic parameter bounds are not annotations and may be spaced: `<T: Ord + Copy>`. A spaced `->` always introduces a return type, so `:fn f x:i64=0 -> i64` has a parameter with default `0` and returns `i64`. Everywhere else whitespace is insignificant except as a token separator and for the newline rules below.

```pika syntax-error
:for i from=1 to=10 do={ :put $i }     # correct
:for i from = 1 to = 10 do = { :put $i }   # error: named arguments must be written name=value
```

### 3.4 Newlines and statement termination

- A statement ends at `;` or at a newline.
- Newlines are **ignored** inside `( )`, `[ ]` and `< >` of a type.
- Newlines are **significant** inside `{ }` (blocks, collection literals, struct and enum bodies), where they separate statements, elements or members.
- A backslash `\` as the last character of a physical line joins it with the next line. A line ending in `\` may not carry a comment. A backslash elsewhere outside a string is an error.
- A command continues after a closing `}` on the same line, so `} else={` works without a backslash.

```pika
:if ($a and \
     $b) do={ :put "both" }      # ok, though the backslash is unnecessary inside ( )

:local total [:sum
    $first
    $second]                     # ok: newlines inside [ ] are ignored
```

### 3.5 Identifiers

`[A-Za-z_][A-Za-z0-9_]*`, case-sensitive. An identifier beginning with `_` is private to its module (section 13.3). `_` alone is the wildcard pattern and the "discard" binding.

Naming conventions (enforced as lints, not errors): `snake_case` for functions, variables and fields; `PascalCase` for types and traits; `snake_case` for enum variants; lowercase for primitive types.

### 3.6 Keywords

Because commands are prefixed with `:`, the set of bare keywords is small:

```
and  or  in  as  true  false  none  some  self  Self  _
```

Built-in command names (section 8) are reserved and may not be used as function names: `local const global set if do while for foreach match break continue return error onerror panic fn struct enum trait impl use extern unsafe test put len typeof tostr assert nothing default`.

### 3.7 Literals

**Integers.** `42`, `1_000_000`, `0xFF`, `0o755`, `0b1010`. Hex digits may be either case. The type of an integer literal is inferred from context and defaults to `i64`. An integer literal is never a float: where a float is expected, write `5.0`. A literal that does not fit its type, such as `300` for a `u8` or `-1` for any unsigned type, is a compile error.

**Floats.** `3.14`, `1e9`, `2.5e-3`, `1_000.5`. A digit is required on both sides of `.`. Defaults to `f64`.

**Booleans.** `true`, `false`.

**Characters.** `'a'`, `'\n'`, `'\u{1F600}'`. Type `char` (a Unicode scalar value).

**Durations.** An integer followed (joined) by one or more unit groups: `ns us ms s m h d w`. Units must appear in descending order and each at most once. Type `Duration`.

```pika fragment
500ms   10s   1m30s   2h   1d12h   1w
```

**Strings.** Double-quoted, may span lines, type `String`.

| Escape | Meaning |
|---|---|
| `\"` `\'` `\\` | double quote, single quote, backslash |
| `\n` `\r` `\t` `\0` | newline, carriage return, tab, NUL |
| `\$` | literal `$` |
| `\xHH` | ASCII character with hex code HH (`00` to `7F`). Use `\u{...}` for anything else |
| `\u{H...}` | Unicode scalar value |
| `\` + newline | line continuation: the newline and leading whitespace of the next line are removed |

**Interpolation** inside a string:

| Form | Meaning |
|---|---|
| `$name` | the variable `name` |
| `$(expr)` | an expression |
| `$[command]` | the result of a command |

Interpolated values must implement `Display` (section 10.4).

```pika
:put "Hello $name, 5x6 = $($a * $b), len = $[:len $items]"
```

**Raw strings.** `r"..."` - no escapes, no interpolation. `r#"..."#` allows `"` inside.

### 3.8 Operators and delimiters

```
(  )  [  ]  {  }  :  ;  $  /  ->  =  ,
+  -  *  /  %  !  ~  &  |  ^  <<  >>  .
=  !=  <  >  <=  >=  &&  ||  ?
```

`==` is not a token. Writing it produces the error "use `=` for equality".

### 3.9 Canonical layout

`pika fmt` rewrites source files in one canonical layout, so that every Pika file looks alike. It changes only the space between tokens: it keeps every line break between statements, every comment, and whether each pair of tokens is joined, except where joining never changes meaning (the space just inside brackets, around binary operators and around `;` and `,`).

- Each line is indented by four spaces for each bracket (`{`, `(`, `[`) left open by the lines before it. A line that starts by closing a bracket is indented like the line that opened it; a line after a `\` continuation, one level more.
- Tokens on a line are separated by one space, or joined where written joined, with these fixed rules: no space just inside `(`, `[`, `$(` and `$[`, or before `)`, `]`, `;` and `,`; one space after `;` and `,`, except in `impl=A,B` and `:foreach i,x`; one space around binary operators; one space just inside the braces of a block on one line (`do={ :put 1 }`); none just inside the braces of a collection or struct literal (`{1; 2}`, `Point{x=1}`) or of an empty pair (`{}`).
- `&&` and `||` are written `and` and `or`.
- No line ends with space, there is at most one blank line in a row and none just inside a bracket, and the file ends with one line break.
- The space before a comment at the end of a line is kept, so that aligned comments stay aligned.

`pika fmt [paths]` formats the given files and the `.pk` files under the given directories, in place; `pika fmt --check` changes nothing, lists the files that are not formatted, and fails if there are any. Files with syntax errors are reported and left as they are. The formatter verifies that the formatted file parses to the same syntax tree as the original.

## 4. Program structure

### 4.1 Statements and commands

Every statement is one of:

1. A **command**: `:name args...`, `/path/to/fn args...`, `Type->member args...`, or `$value args...` (a call through a function value or a method).
2. A **scope block**: `{ statements }`, which introduces a new lexical scope.

A command consists of a **head** followed by zero or more **arguments**. An argument is either positional (an *atom*) or named (`name=atom`).

An **atom** is one of:

- a literal
- a variable read: `$name`, optionally followed by member access: `$p->x`, `$list->0`, `$m->"key"`, `$grid->($i + 1)`
- a path value: `/math/pi`
- a static member: `Color->red`
- a parenthesized expression: `( expr )`
- a command substitution: `[ command ]`
- a collection or struct literal: `{...}`, `Point{...}`

Operators are **not** allowed in argument position without parentheses. This is what makes whitespace-separated arguments unambiguous.

```pika syntax-error
:put ($a + $b)     # ok
:put $a + $b       # error: operators in arguments must be parenthesized
:put -5            # ok: negative literal
:put (-$x)         # ok
```

### 4.2 Command substitution

`[ command ]` runs the command and yields its return value. It contains exactly one command.

```pika
:local n [:len $items]
:put [/math/sqrt [:tofloat $n]]
```

### 4.3 Expressions

Expressions appear inside `( )` and in interpolation `$( )`. Inside an expression, operands are atoms and operators may be used freely. Bare identifiers are not values; variables are always read with `$`.

### 4.4 Entry point and script mode

- A program's entry module (the file of a single-file program, or `src/main.pk` of a binary package) either declares `:fn main` or contains top-level statements (**script mode**), not both.
- In script mode, top-level statements form an implicit `main`. Top-level `:local` variables are locals of that `main` and are not visible to functions; top-level `:const` and `:global` declarations are module-level and visible everywhere.
- Non-entry modules may contain only declarations.
- `main` may be declared `raises`. An uncaught error is reported on stderr (section 9.2) and the program exits with status 1.

```pika
# hello.pk - script mode
:put "Hello, Pika"
```

## 5. Types

### 5.1 Primitive types

| Type | Description |
|---|---|
| `i8 i16 i32 i64` | signed integers |
| `u8 u16 u32 u64` | unsigned integers |
| `int` | alias for `i64`. Used for lengths and indexes |
| `f32 f64` | IEEE-754 floats. `float` is an alias for `f64` |
| `bool` | `true` / `false` |
| `char` | Unicode scalar value |
| `nothing` | unit type with the single value `[:nothing]`. The return type of functions without `->` |
| `never` | type of expressions that do not return (`:panic`, `:return`, `:break`) |

v0 targets 64-bit platforms only. There is no `usize`; lengths and indexes are `int`.

### 5.2 Standard types (prelude)

| Type | Description |
|---|---|
| `String` | owned, growable, UTF-8 |
| `List<T>` | owned, growable, contiguous |
| `Map<K, V>` | owned hash map, **insertion-ordered**. `K: Hash + Eq` |
| `Set<T>` | owned hash set, insertion-ordered |
| `Option<T>`, written `T?` | `some value` or `none` |
| `Box<T>` | owned heap allocation (for recursive types) |
| `Duration` | signed nanosecond count |
| `Error` | the error type carried by `raises` (section 9) |
| `Ptr<T>` | raw pointer, usable only in `:unsafe` code (section 13) |

### 5.3 Compound type syntax

```
Type      := Name GenericArgs? | Path GenericArgs? | Type "?" | FnType | "Self"
FnType    := "fn" "(" (Type ("," Type)*)? ")" ("->" Type)? "raises"?
GenericArgs := "<" Type ("," Type)* ">"
```

Examples: `List<String>`, `Map<String, List<i64>>`, `Point?`, `fn(i64, i64) -> i64`, `/net/Url`.

### 5.4 No implicit conversions

There are no implicit numeric conversions, no truthiness, and no implicit string conversion outside interpolation and `:put`. Use `as` for numeric casts.

```pika
:local a:i32 10
:local b:i64 ($a as i64)
:if ($count > 0) do={ :put "some" }     # ok
:if ($count) do={ :put "some" }         # error: expected bool, found i64
```

`as` is defined only between numeric types and from `char` to `u32`. Float-to-int casts saturate. Int-to-int casts that lose information trap at runtime; use `/std/num/truncate` for explicit truncation.

The single implicit conversion is **option wrapping**: a value of type `T` is accepted where `T?` is expected.

### 5.5 Type inference

- Function parameter and return types are always explicit.
- `:local`, `:const` and literal types are inferred bidirectionally within a function body.
- An unconstrained integer literal is `i64`, an unconstrained float literal is `f64`.
- Empty collection literals need an annotation or an inferable context: `:local xs:List<i64> {}` or `List<i64>{}`.

## 6. Variables and bindings

```pika
:local x 5              # mutable binding, type inferred (i64)
:local y:f64 1.0        # mutable binding with annotation
:local z:String         # declared, not initialized
:const limit 100        # immutable binding
:set x ($x + 1)         # assignment
:set ($p->x) 2.0        # assignment to a field
:set ($list->0) 7       # assignment to an element
:set ($map->"k") 1      # insert or update a map entry
```

- `:local` declares a mutable binding. `:const` declares an immutable binding.
- A variable must be definitely assigned before it is read (checked at compile time).
- Shadowing in a nested scope is allowed. Redeclaring a name in the same scope is an error.
- A `:local` that is never `:set` produces a lint suggesting `:const`.
- Assignment is a statement (`:set`), never an expression.

### 6.1 Module-level declarations

- `:const NAME value` at module level declares a compile-time constant. Its initializer must be const-evaluable (literals, arithmetic, other constants, and calls to functions the compiler can evaluate at compile time).
- `:global NAME:Type value` declares a module-level mutable variable with a const-evaluable initializer. v0 is single-threaded; when concurrency arrives, globals will require a synchronization wrapper. Any function reading or writing a global is fine in v0.
- Collections and boxes are allocated when the program runs, so they cannot be built at compile time; a constant or global collection starts empty: `:global log:List<String> {}`.

### 6.2 Scopes

A variable is visible from its declaration to the end of the enclosing block, including nested blocks. Each `do={}`, `else={}`, `in={}` and `{ }` is a block.

## 7. Expressions and operators

### 7.1 Precedence (highest first)

| Level | Operators | Associativity |
|---|---|---|
| 1 | `->` member/index | left |
| 2 | unary `-` `!` `~` | prefix |
| 3 | `as` | left |
| 4 | `*` `/` `%` | left |
| 5 | `+` `-` | left |
| 6 | `<<` `>>` | left |
| 7 | `&` | left |
| 8 | `^` | left |
| 9 | `\|` | left |
| 10 | `.` concatenation | left |
| 11 | `=` `!=` `<` `>` `<=` `>=` `in` | non-associative |
| 12 | `&&` `and` | left |
| 13 | `\|\|` `or` | left |

`and`/`&&` and `or`/`||` are synonyms. The formatter normalizes to `and` and `or` (section 3.9).

### 7.2 Semantics

- **Arithmetic** works on matching numeric types. Integer overflow **traps** in every build mode. Wrapping, saturating and checked variants are available as methods (`[$a->wrapping_add $b]`).
- **Integer division** truncates toward zero. `%` takes the sign of the dividend. Division or remainder by zero traps, and so does dividing the smallest value of a signed type by `-1`; the remainder of that division is `0`.
- **Bitwise** `~ & | ^ << >>` work on integers. Both operands of `& | ^` have the same type; the shift amount of `<<` and `>>` may be any integer type. Shifting by at least the bit width traps.
- **Durations** support `+` and `-` between durations, unary `-`, and comparisons.
- **Concatenation** `.` works on `String . String` and `List<T> . List<T>`, producing a new value. Interpolation is usually clearer for strings.
- **Comparison** `=` and `!=` require `Eq`. `< > <= >=` require `Ord`. Chained comparisons like `($a < $b < $c)` are an error.
- **Membership** `($x in $c)` works on `List`, `Set`, `Map` keys and `String` substrings.
- **Operator traits.** `+ - * / % .` and unary `-` on structs, enums and type parameters call the functions of the operator traits (section 10.4).
- **Logical** `and`, `or` short-circuit and require `bool` operands. `!` negates a `bool`.
- **Evaluation order.** Operands, the pieces of an interpolated string, the elements of a literal and the arguments of a call are evaluated left to right, as written. Each value is taken when it is evaluated: in `"$n $[:bump $n] $n"`, where `:bump` increments `n`, the first `$n` shows the old value and the last the new one.

### 7.3 Member and index access: `->`

`->` is the single access operator.

| Form | Meaning |
|---|---|
| `$v->name` | field `name`, or method `name` when used as a command head |
| `$v->0`, `$v->"k"`, `$v->$i`, `$v->(expr)` | index |
| `Type->name` | static member: enum variant, associated function or associated constant |

In v0, indexing is built in for `List`, `Map` and fixed-size arrays. Indexing out of bounds, or reading a missing map key, **panics**. Use `[$list->get $i]` or `[$map->get $k]` for a `T?` result. Strings are not indexable; use `[$s->chars]` or `[$s->bytes]`.

- A list index is an `int` from 0 to the length, exclusive; a negative index panics too.
- `:set ($list->$i) value` replaces an element, which must exist. `:set ($map->$k) value` inserts the key, or replaces its value.
- An element is a place, like a field: it can be read, borrowed, assigned and passed to a `mut` parameter (`:grow $list->0`), but not moved out of its collection unless it is `Copy`; take it out with `[$list->remove $i]` or `[$map->remove $k]`.

## 8. Commands and control flow

Control-flow commands are syntax: their named arguments (`do`, `else`, `in`, `from`, ...) are fixed and parsed specially. Every other command is an ordinary function call.

### 8.1 Conditionals

```pika
:if ($x < 0) do={
    :put "negative"
} else=:if ($x = 0) do={
    :put "zero"
} else={
    :put "positive"
}
```

The condition must be `bool` and must be parenthesized. `else=` accepts either a block or another `:if` command.

### 8.2 Loops

```pika
:while ($n > 0) do={ :set n ($n - 1) }

:do {
    :set n ($n + 1)
} while=($n < 10)

:for i from=0 to=10 do={ :put $i }            # inclusive: 0..=10
:for i from=0 until=10 do={ :put $i }         # exclusive: 0..<10
:for i from=10 to=0 step=-2 do={ :put $i }    # 10, 8, ..., 0

:foreach x in=$list do={ :put $x }            # elements
:foreach i,x in=$list do={ :put "$i: $x" }    # index, element
:foreach k,v in=$map do={ :put "$k=$v" }      # key, value, in insertion order
:foreach mut x in=$list do={ :set x ($x * 2) }   # mutate elements in place
```

- `:for` takes exactly one of `to=` (inclusive) or `until=` (exclusive). `step=` defaults to `1` and must not be `0` (compile error when constant, panic otherwise). The loop variable is an immutable integer of the type of `from=`. `from=`, the bound and `step=` are evaluated once, in that order, before the first iteration. The loop stops when the next value would pass the bound, so it never overflows: `:for b from=(0 as u8) to=255` runs 256 times.
- `:foreach` borrows the collection for the duration of the loop. Loop variables are read-only borrows of the elements unless `mut` is given. The body may not move, mutate or `:set` the collection being iterated (compile error).
- Over a list, the names are the index (an `int`) and the element; over a map, the key and the value, in insertion order; with one name, the element or the value. A set has elements only: one name, which cannot be `mut`. `mut` applies to the element or value: `:foreach mut k,v in=$map`.
- A temporary collection (`:foreach x in=[:load]`) is owned by the loop and destroyed after it.
- `:break` and `:continue` apply to the innermost loop.

### 8.3 Pattern matching

```pika fragment
:match $value {
    Pattern do={ ... }
    Pattern if=(guard) do={ ... }
}
```

Patterns:

| Pattern | Matches |
|---|---|
| `_` | anything, binds nothing |
| `name` | anything, binds it as `$name` |
| literal | equal value (integers, chars, strings, bools) |
| `Enum->variant p1 p2 ...` | that variant, with positional sub-patterns for its fields |
| `some p` / `none` | option cases |

Matches must be exhaustive. Arms are tried in order. When the scrutinee is a place (a variable or field), bindings are read-only borrows. When it is a temporary, bindings take ownership.

- Literal patterns are integers (optionally negative), characters, strings without interpolation, and `true`/`false`. Floats and durations cannot be patterns; bind the value and compare it in a guard.
- A variant pattern gives one sub-pattern per field, in order. A sub-pattern that is itself a variant with fields, or `some p`, is written in parentheses: `Shape->pair (some x) _`.
- A guarded arm does not count toward exhaustiveness. A `:match` that does not cover every value is an error that names a value no arm matches; an arm that no value can reach is warned about.
- While an arm whose names borrow from a place runs, that place cannot be assigned, moved or passed to a `mut` parameter. Names bound to `Copy` values are copies and borrow nothing.
- A global matched on is copied first, like any read of a global.

`:match` is a statement in v0.

### 8.4 Built-in commands

| Command | Description |
|---|---|
| `:put value` | print `value` (must be `Display`) and a newline to stdout |
| `:len value` | length of a `String` (bytes), `List`, `Map` or `Set`, as `int` |
| `:tostr value` | `Display` formatting as a `String` |
| `:typeof value` | the static type name, as a `String` (compile-time) |
| `:assert (cond) message?` | panic with a message if `cond` is false |
| `:panic message` | abort the program (section 9.3) |
| `:nothing` | the unit value |
| `:default` | the default value of the expected type, or of `T` in `[:default<T>]` (section 10.4) |
| `:error value` | raise an error (section 9) |
| `:return value?` | return from the function |

Further helpers live in the standard library as ordinary functions (section 13.5), such as `/std/strings/find` and `/std/strings/parse_int`.

## 9. Errors

Pika separates **errors** (expected, recoverable failures) from **panics** (bugs).

### 9.1 Raising

A function that can fail declares `raises`. `:error` raises an `Error`: `:error "message"` makes one with that message and the location of the `:error`, `:error "message" source=$e` also records the error `$e` that caused it, and `:error $e` raises the error `$e` as it is.

```pika
:fn read_config path:String -> Config raises do={
    :const text [/fs/read? $path]         # /fs/read raises; `?` passes its error on
    :if ([:len $text] = 0) do={ :error "empty config: $path" }
    :return [Config->parse? $text]
}
```

- A call of anything that can raise an error, a function, method or associated function declared `raises`, or a function value of type `fn(...) raises`, has a `?` joined to its head, after its type arguments if any: `[/fs/read? $path]`, `[$text->parse_int?]`, `[:load<Config>? $path]`, `[$f? 1]`. The `?` shows where an error can come from; it does not change what the call does. A call that can raise without `?`, and a `?` on a call that cannot raise, are compile errors.
- Inside a `raises` function, an error raised by a call passes on to the function's caller.
- Calling a `raises` function, or using `:error`, outside a `raises` function is a compile error unless it is inside the `in=` block of an `:onerror`.
- When an error leaves a scope, the values owned there are destroyed as usual (section 12.1), from the innermost scope outwards.
- Errors are implemented as ordinary return values. There is no stack unwinding, so `raises` has a predictable, low cost.
- A method or trait function may be `raises`. A type's version of a trait function is `raises` exactly when the trait's function is. `fmt`, `drop` and `default` cannot raise.

### 9.2 Catching

```pika
:onerror e in={
    :const cfg [:read_config? "app.toml"]
    :put "loaded $($cfg->name)"
} do={
    :put "could not load config: $e"
}
```

An error raised in the `in=` block, directly or by a call, stops it and runs the `do=` block. `$e` has type `Error` and is in scope only in the `do=` block, which owns it; an error raised in the `do=` block goes to the enclosing `:onerror`, or leaves the function. `:onerror` statements nest: the innermost catches.

`Error` is a struct declared by the language:

```pika
:struct Error impl=Clone,Display {
    message:String
    source:Box<Error>?=none    # the error that caused it, from `source=`
    file:String=""             # where `:error` raised it: the source file,
    line:u32=0                 # the line
    column:u32=0               # and the column
    trace:List<String>={}      # the calls it came out of, as `file:line:column`, innermost first
}
```

An error raised by a call is added to the trace of the error at that call, whether the error passes on with `?` or an `:onerror` catches it: the trace shows the way the error came, from where it was raised. An error displays as its message. Its fields can be read like any struct's (`$e->message`, `:match $e->source {...}`), and `Error{message="..."}` makes one without a location. In v0 there is a single `Error` type; typed errors are planned for v1.

**Uncaught errors.** When `main` is declared `raises` and raises an error, the program prints the error and the errors that caused it to standard error, after flushing standard output, and exits with status 1:

```
error: could not load config
  at app.pk:5:9
    5 |         :error "could not load config" source=$e
      |         ^
caused by: empty config: app.toml
  at app.pk:2:33
    2 |     :if ([:len $text] = 0) do={ :error "empty config: $path" }
      |                                 ^
  called at app.pk:4:17
```

Each error gives where it was raised, with the line of the source and a `^` under the column, then each call it came out of. Source lines in reports, here and in compiler diagnostics, are shown without their comments.

### 9.3 Panics

Panics come from `:panic`, failed `:assert`, integer overflow, division by zero, out-of-bounds indexing and missing map keys. A panic flushes standard output, prints a report to standard error, and terminates the process with status 101. The report has the form:

```
panic: integer overflow
  at app.pk:12:10
    12 |     :put ($total * $count)
       |          ^
```

For `:assert`, the first line is `panic: assertion failed: <message>`, where the message is the condition as written when none is given; when the condition compares two values that can be displayed (`=`, `!=`, `<`, `<=`, `>`, `>=`), two more lines give their values, `  left: <value>` and ` right: <value>`, and each side is evaluated once. For `:panic`, the first line is `panic: <message>`. Panics cannot be caught. There is no unwinding; destructors do not run on panic.

## 10. User-defined types

### 10.1 Structs

```pika
:struct Pair<A, B> impl=Eq {
    first:A
    second:B
    count:i64=0                 # field default

    :fn swap owned self -> Pair<B, A> do={
        :return Pair<B, A>{first=$self->second; second=$self->first}
    }
}
```

- Fields are declared `name:Type`, optionally with a default written `name:Type=value` (joined, like named arguments).
- Construction uses a struct literal `Name{field=value; ...}`. Fields with defaults may be omitted. Inside the struct, `Self` names the type.
- Fields are private to the module if they begin with `_`.
- Methods and associated functions are declared inside the body with `:fn` (section 11.3).

### 10.2 Enums

```pika
:enum Token {
    number value:f64
    ident name:String
    plus
    minus
}

:local t [Token->number 3.5]      # variant with fields: a constructor command
:local u Token->plus              # unit variant: a value
```

Variants with fields are constructed like commands, with positional or named arguments. Unit variants are values. Enums may declare methods and `impl=` like structs. Fields of a variant are read with `:match`; enums have no `->field` access.

A derived `Eq` and `Ord` compare the variant first, in declaration order, then the fields of the variant in order. A derived `Display` writes `Token->plus` for a variant without fields and `Token->number{value=3.5}` for one with fields.

**Options.** `T?` holds `some` value or `none`. `[some $x]` constructs one and `none` is a value (its type is inferred). Methods: `[$o->is_some]`, `[$o->is_none]`, `[$o->unwrap]` (takes the option; panics on `none`), `[$o->unwrap_or $default]` (takes both), `[$o->take]` (a `mut` borrow: returns the value and leaves `none`) and `[$o->clone]`. An option is `Copy`, `Clone`, `Eq` or `Ord` when its value type is, with `none` before every `some`; it displays as `none` or `[some 3]`, with strings and characters quoted.

### 10.3 Traits

```pika
:trait Shape {
    :fn area self -> f64
    :fn describe self -> String do={      # default method
        :return "shape with area $([$self->area])"
    }
}

:struct Square impl=Shape {
    side:f64
    :fn area self -> f64 do={ :return ($self->side * $self->side) }
}
```

- A trait declares functions: **required** ones are signatures without a body, which every implementing type defines; **default** ones have a body, which a type may replace with its own. Functions without `self` are associated functions, such as constructors: `:fn make -> Self`.
- Inside a trait, `Self` is the implementing type. A default function may use everything the trait and the traits it requires provide: `[$self->area]`, `[Self->make]`, and `$self` in a string when the trait requires `Display`.
- A type declares the traits it implements with `impl=Trait1,Trait2` (comma-separated, no spaces), mixed freely with derived built-in traits. It defines each required function in its body, with the same signature as in the trait: the same parameters, conventions, types, return type and type parameters with the same bounds, with `Self` replaced by the type. A type gets the default functions it does not define.
- Traits may require other traits, built-in or user-defined: `:trait Ordered impl=Eq { ... }`. A type implementing a trait must list the traits it requires in its own `impl=`. A trait that requires built-in traits holds, like a derived trait, for the type arguments for which the type has them: with `:trait Pretty impl=Display`, `Wrap<i64>` implements `Pretty` but `Wrap<T>` for a `T` without `Display` does not.
- A type parameter bounded by a trait, `<T: Shape>`, has the functions of the trait and of the traits it requires: `[$x->area]` on a value, `[T->make]` for associated functions. A name found in two of its traits is ambiguous and an error; so is a function a type would get from two of its traits without defining it itself.
- Parameters of a trait's functions cannot have default values.
- Calls are resolved statically, per instance (section 10.6): a call of a trait's function on a type runs that type's version, or the trait's default.
- A trait is not a type: `x:Shape` is an error. Trait objects (`dyn`) are planned for v1.
- In v0 a trait can only be implemented in the type's own declaration, and traits have no type parameters. Implementing traits for types declared elsewhere (extensions) and generic traits are planned for v1.

### 10.4 Built-in traits

| Trait | Purpose | Function of an implementing type | Derivable |
|---|---|---|---|
| `Copy` | implicitly copied instead of moved. Only valid when every field is `Copy` | | yes |
| `Clone` | explicit deep copy: `[$x->clone]` | | yes |
| `Drop` | destructor | `:fn drop mut self` | no |
| `Eq` | `=` and `!=` | | yes |
| `Ord` | `< > <= >=` | | yes (field order) |
| `Hash` | map and set keys | | yes |
| `Display` | `:put`, `:tostr`, interpolation | `:fn fmt self mut out:Formatter` | yes (`Name{a=1; b=2}`) |
| `Default` | `[:default]` | `:fn default -> Self` | yes, for structs |
| `Add Sub Mul Div Rem` | `+ - * / %` | `:fn add self other:Self -> Self`, and `sub`, `mul`, `div`, `rem` | no |
| `Neg` | unary `-` | `:fn neg self -> Self` | no |
| `Concat` | the `.` operator | `:fn concat self other:Self -> Self` | no |

**Deriving.** Listing a derivable trait in `impl=` without defining its function asks the compiler to derive it. `:struct Point impl=Copy,Eq,Display { ... }`. A derived trait requires every field to implement it. A type that lists `Display` or `Default` and defines `fmt` or `default` uses its own function instead, and its fields need not implement the trait.

- Derived `Eq` and `Ord` compare fields in declaration order: the first pair of fields that differ decides. If that pair is unordered (a float field holding `NaN`), the values are unordered: `=`, `<`, `<=`, `>` and `>=` are `false` and `!=` is `true`. Deriving `Ord` also provides `Eq`.
- Derived `Display` writes `Name{field=value; ...}` with the fields in declaration order. `String` and `char` fields are written as literals, quoted and escaped, so that the text reads back as the value: `Person{name="Ada \"A\" L"; initial='A'; age=36}`.
- Derived `Clone` clones every field; a `Copy` struct is also `Clone`.
- Derived `Default` gives each field its default value when it has one (`name:String="app"`), and otherwise the default of its type. Enums have no default variant to derive, but may define `:fn default -> Self`.

**Built-in defaults.** Numbers are `0` and `0.0`, `bool` is `false`, `char` is `'\0'` (code point 0), `String` is `""`, `Duration` is `0s`, collections are empty, options are `none`, and `Box<T>` boxes the default of `T`. `[:default]` takes its type from the expected type (`:local c:Config [:default]`) or from `[:default<Config>]`; it is not a constant expression.

```pika
:struct Vec2 impl=Copy,Add,Neg,Display,Default {
    x:f64
    y:f64
    :fn add self other:Self -> Self do={ :return Vec2{x=($self->x + $other->x); y=($self->y + $other->y)} }
    :fn neg self -> Self do={ :return Vec2{x=(-$self->x); y=(-$self->y)} }
    :fn fmt self mut out:Formatter do={ $out->write "($($self->x), $($self->y))" }
}

:struct TempFile impl=Drop {
    path:String
    :fn drop mut self do={ :put "removing $($self->path)" }
}

:local v:Vec2 [:default]                 # Vec2 with x=0.0 and y=0.0
:set v ($v + -Vec2{x=1.0; y=2.0})
:put $v                                   # (-1.0, -2.0)
```

**Display with `fmt`.** A type's `fmt` writes its text into a `Formatter` with `$out->write value`, which appends the text of any `Display` value (strings without quotes). The text of a value with a `fmt` is exactly what `fmt` writes, wherever the value is displayed: printed, interpolated, or inside a collection, an option or another type's derived `Display`. `Formatter` is a built-in type that only `fmt` receives; it has no other operations, and it may be passed on as a `mut` parameter to functions that write parts of the text.

**Drop.** A value whose type implements `Drop` runs `drop` when it is destroyed (section 12.1): its own `drop` first, then the destruction of its fields, so an outer value's `drop` sees its parts whole. A type cannot be both `Copy` and `Drop`. `drop` cannot be called directly, no part can be moved out of such a value (a `:match` on a temporary that binds a part by value is an error), and the evaluation of a constant cannot destroy such a value.

**Operators.** `($a + $b)` on values of a struct, enum or type parameter calls the `add` of the `Add` trait, and so on for each operator trait; both operands and the result have the same type. Built-in numbers implement `Add Sub Mul Div Rem`, signed numbers and `Duration` implement `Neg`, `Duration` implements `Add` and `Sub`, and `String` and lists implement `Concat`, so `<T: Add>` accepts them too. The traits that operators call (`Add Sub Mul Div Rem Neg Concat Drop`) are declared by the language and cannot be redeclared. Comparisons use `Eq` and `Ord`, which are derived only. `Contains` (the `in` operator for user-defined types) needs a trait with a type parameter for the element, and is planned for v1 with generic traits.

Integers, floats, `char`, `String` and `Duration` implement `Ord`; `bool` and `nothing` implement only `Eq`. Integers, `bool`, `char`, `String`, `Duration` and `nothing` implement `Hash`; floats do not, so they cannot be map keys or set elements. Options and boxes implement `Hash` when their value does; collections do not.

All primitive types except `nothing`, and `String` and `Duration`, implement `Display`, which formats them as follows:

| Type | Format | Examples |
|---|---|---|
| integers | decimal | `42`, `-7` |
| floats | shortest text that reads back as the same value; whole numbers keep `.0`; magnitudes below `1e-5` or from `1e16` use an exponent | `0.1`, `3.0`, `1e300`, `1.5e-7`, `NaN`, `inf`, `-inf` |
| `bool` | `true` or `false` | |
| `char` | the character itself | `A` |
| `Duration` | the literal syntax, largest unit first; zero is `0s` | `1m30s`, `500ms`, `-2h` |
| `String` | the text itself | |
 Primitive types, `Duration` and `Option<T: Copy>` are `Copy`. `String`, `List`, `Map`, `Set` and `Box` are `Clone` but not `Copy`.

### 10.5 Collections

`List<T>` is a growable sequence. `Map<K, V>` maps keys to values and `Set<T>` holds distinct elements, both in **insertion order**; keys and set elements must implement `Hash` and `Eq`.

A collection literal is written in braces, with elements separated by `;` or newlines: `{1; 2; 3}` is a list and `{"ada"=36; "alan"=41}` a map. The type comes from a type written before the brace (`Set<String>{"a"; "b"}`, `List<i64>{}`), or from the expected type (`:local seen:Set<i64> {}`), or from the elements (values make a list, `key=value` entries a map); an empty literal needs one of the first two. Map keys are values, so a string key is quoted: `{"a"=1}`. In a map or set literal, a repeated key keeps its first position and its last value.

| Method | List | Map | Set |
|---|---|---|---|
| `len`, `is_empty` | count | count | count |
| `clear` | removes all | removes all | removes all |
| `push value` | appends | | |
| `pop` | `T?`, removed from the end | | |
| `insert` | `index value`: inserts at `index` (0 to the length) | `key value`: inserts or replaces; the old value, as `V?` | `value`: `bool`, whether it was added |
| `remove` | `index`: the element, removed | `key`: the value, as `V?` | `value`: `bool`, whether it was there |
| `swap` | `i j`: exchanges two elements | | |
| `get` | `index`: a copy, as `T?` | `key`: a copy, as `V?` | |
| `contains` | `value` (`T: Eq`) | `key` | `value` |
| `keys`, `values` | | lists of copies, in order | |
| `clone` | a deep copy | a deep copy | a deep copy |

Methods that change a collection need a variable (or a `mut` parameter) that may be modified. `($x in $c)` is `contains`. `($a . $b)` makes a new list of copies of the elements of both.

A collection is `Clone`, `Eq` and `Display` when its elements are. Lists compare element by element, and a list that is a prefix of another is smaller; maps and sets are equal when they have the same entries in any order, and have no `<`. They display as literals, with strings and characters quoted: `{1; 2}`, `{"a"=1; "b"=2}`.

### 10.6 Generics

Functions, structs and enums may have type parameters, written after the name. A parameter may be bounded by traits, joined with `+`:

```pika
:fn largest<T: Ord + Clone> items:List<T> -> T? do={
    :local best:T? none
    :foreach item in=$items do={
        :match $best {
            some b if=($b >= $item) do={}
            _ do={ :set best [some [$item->clone]] }
        }
    }
    :return $best
}

:struct Stack<T: Clone> impl=Clone,Display {
    items:List<T>
    :fn push mut self owned x:T do={ $self->items->push $x }
    :fn with<U: Clone> self owned x:U -> Stack<U> do={   # a function's own parameters
        :return Stack{items={$x}}
    }
}

:enum Tree<T> impl=Clone {
    leaf
    node left:Box<Tree<T>> value:T right:Box<Tree<T>>
}
```

- **Bounds.** A bound is a built-in trait (`Copy`, `Clone`, `Eq`, `Ord`, `Hash`, `Display`) or a user-defined trait (section 10.3). A generic body may only use a value of a parameter type in ways that every type meeting the bounds allows: `<` needs `Ord`, `=` needs `Eq`, `:put` and interpolation need `Display`, `[$x->clone]` needs `Clone`, and a map key or set element needs `Hash + Eq`. A value of type `T` is moved, not copied, unless `T: Copy`.
- **Type arguments** are inferred from the arguments and from the expected type, or written after the name: `[:largest<String> $words]`, `[$stack->with<f64> 1.5]`, `Stack<i64>{items={}}`, `[Stack<i64>->new]`. A variant takes the enum's type arguments before `->`: `Tree<i64>->leaf`. A type parameter of a struct or enum is in scope in its fields and functions; a function of the type may add its own parameters after them.
- **Bounds of types.** The bounds of a struct's or enum's parameters must hold wherever the type is written with arguments: with `:struct Sorted<T: Ord>`, `Sorted<bool>` is an error.
- **Derived traits** of a generic type hold for the type arguments for which every field has the trait: `Pair<i64, String>` is `Eq` and `Hash`, `Pair<f64, String>` is not `Hash`, and a `Copy` struct holding a `String` is not `Copy`.
- **Defaults.** A parameter or field whose type contains a type parameter cannot have a default value, since a default is a constant.
- **Checking.** A generic function is type checked and ownership checked once, for every type argument its bounds allow; its errors are reported in its body, not at each call.
- **Instances.** Generics are monomorphized: each distinct list of type arguments a generic function is called with produces its own compiled function, specialized to those types. A generic function that calls itself with ever larger types (`T`, then `List<T>`, then `List<List<T>>`, ...) needs infinitely many instances, which is an error.
- `main` cannot have type parameters.
- A derived `Display` writes the type's name without its arguments: `Pair{first=1; second="a"}`. `:typeof` includes them: `Pair<i64, String>`.

## 11. Functions

### 11.1 Declaration

```
:fn name<GenericParams>? param* ("->" Type)? "raises"? do={ body }
param := convention? name ":" Type ("=" default)?
convention := "mut" | "owned"
```

```pika
:fn add a:i64 b:i64 -> i64 do={ :return ($a + $b) }

:fn greet name:String greeting:String="Hello" do={
    :put "$greeting, $name"
}

:fn max<T: Ord + Copy> a:T b:T -> T do={
    :if ($a > $b) do={ :return $a }
    :return $b
}
```

Without `->`, the return type is `nothing`. A function whose return type is not `nothing` must return on every path (checked). A statement does not finish if it is `:return`, `:break`, `:continue`, `:panic`, a call to a function returning `never`, an `:if` whose branches all do not finish, or a `:while (true)` loop without `:break`. Code after such a statement is reported as unreachable.

Default values of parameters must be constant: literals, operators, casts and module-level constants.

### 11.2 Calls

Functions are commands. Arguments may be positional, named, or both (positional first). Named arguments may appear in any order; they are evaluated in the order written (section 7.2), then bound to their parameters. Defaults fill omitted arguments.

```pika
:greet "Ada"
:greet "Ada" greeting="Hi"
:greet name="Ada" greeting="Hi"
:local m [:max<f64> 1.5 2.5]       # explicit generic arguments
:local n [:max 1 2]                # inferred
```

Module functions use a path head: `[/math/sqrt 2.0]`. Function values are called with `$` as the head: `[$callback 1 2]`.

### 11.3 Methods

A function declared inside a type body whose first parameter is `self` is a method. Its convention is written before `self`.

| Receiver | Meaning |
|---|---|
| `self` | read-only borrow |
| `mut self` | mutable borrow |
| `owned self` | takes ownership |

Methods are called with `->` on a value: `[$p->dist $q]`, or as a statement: `$list->push 5`. A function in a type body without `self` is an associated function: `[Point->new 1.0 2.0]`.

The value a method is called on can be any atom: a variable, a command's result (`[[$line->trim]->split ","]`), a parenthesized expression (`[(-$x)->abs]`) or a literal (`["a,b"->split ","]`, `[2.0->sqrt]`). A method called on a number whose type is not inferred yet gives it its default type, `i64` or `f64`.

#### Functions of built-in types

Built-in types have the built-in methods of their sections (5, 10.5) and the functions that the standard library declares for them with `:impl`:

```pika fragment
:impl String {
    :fn trim self -> String do={ ... }
}
:impl<T: Ord> List<T> {
    :fn sort mut self do={ ... }
}
```

- The type of an `:impl` is a built-in type, generic over the impl's type parameters (`List<T>`), or one instance of it (`List<String>`). Its functions have the impl's type parameters and bounds, so `[$list->sort]` needs elements that are `Ord`.
- `[String->from_chars $chars]` calls an associated function of a built-in type; for a generic type, the type arguments are inferred unless written (`[List<i64>->range 0 3]`).
- Only the standard library declares `:impl`, so that two packages never give a type conflicting functions; a package adds functions to its own types in their bodies. A function of an `:impl` cannot have the name of a built-in method of its type, nor of another function of an `:impl` of the same built-in type.

### 11.4 Function values and closures

`[:fn ...]` without a name creates an anonymous function value:

```pika
:fn apply f:fn(i64) -> i64 x:i64 -> i64 do={ :return [$f $x] }

:fn main do={
    :const double [:fn x:i64 -> i64 do={ :return ($x * 2) }]
    :put [$double 21]

    :const factor 3
    :const scale [:fn x:i64 -> i64 do={ :return ($x * $factor) }]   # captures factor
    :put [:apply $scale 5]                                            # 15
}
```

- Function value types are written `fn(A, B) -> R`, with `raises` at the end for function values that may raise an error. Two function values have the same type when their parameters, result and `raises` are the same, whatever they capture. In a declaration, a `raises` right after a function type belongs to that type: `:fn f -> fn(i64) -> i64 raises do={...}` returns a function value that raises; a function that also raises itself writes `raises` twice.
- `[:fn params -> R do={...}]` creates a function value. Its parameters are borrowed for reading (no `mut`, `owned` or default values), it has no name, and it may be declared `raises`. It is checked like a function, with the type parameters of the function around it.
- Function values **capture** the variables of the enclosing functions that their body uses, **by value**, when they are created: `Copy` values are copied and other values are moved in, so the variable cannot be used afterwards (section 12.1). A variable that is a borrowed parameter cannot be moved in; capture a copy (`:const mine [$s->clone]`).
- A function value can only **read** what it captured: assigning, modifying or moving a captured variable inside it is an error. A function value created inside another one captures a clone of the captured values it uses, which must be `Clone`.
- Function values are `Clone` but not `Copy`, whatever they capture: a clone (`[$f->clone]`) shares the captured values, which are destroyed when the last clone is. They are passed to `read` parameters by borrowing, like other values, and have no other traits.
- `[$f args]` calls a function value with positional arguments. A field holding a function value is called like a method, `[$button->on_click 3]`, when the type has no method of that name.
- A named function without type parameters, whose parameters are all borrowed for reading, can be used as a value with `$name`.

## 12. Ownership and memory

Pika manages memory with ownership, moves and deterministic destruction, with no garbage collector and no user-visible references or lifetimes.

### 12.1 Values, moves and copies

- Every value has exactly one owner: a variable, a field, a collection slot or a temporary.
- Binding, `:set`, passing to an `owned` parameter, returning, and capturing in a closure **move** a value. After a move the source variable cannot be used until it is reassigned (checked at compile time).
- `Copy` types are copied instead of moved.
- `String` values are copied too: binding a string, passing it to an `owned` parameter or taking it from a field or an element copies it, so strings are never moved out of variables. A copy is cheap: copies share their text until one of them changes, and changing a string whose text is shared first gives it its own (copy on write). Strings are not `Copy`, so generic code with a type parameter `T` still moves values of `T`.
- Only whole variables can be moved out of. Moving out of a field or collection element is an error unless the type is `Copy` or `String`; use `[$x->clone]`, `[$list->remove $i]` or `[$opt->take]`.
- When an owner goes out of scope, its value is destroyed (its `Drop` runs, then its fields are destroyed in declaration order). Locals are destroyed in reverse order of declaration.

```pika
:local a {1; 2}
:local b $a              # move
:put $a                  # error: use of moved value `a`
:local c [$b->clone]     # explicit copy
:local s "hello"
:local t $s              # strings are copied
:put "$s $t"             # fine
```

### 12.2 Argument conventions and borrowing

Borrows exist only for the duration of a single call or `:foreach`/`:match`. They cannot be stored, so no lifetime annotations are ever needed.

| Parameter | Caller passes | Callee may |
|---|---|---|
| `x:T` (read, default) | any value or place; borrowed read-only | read |
| `mut x:T` | a mutable place (rooted in a `:local`, a `:global` or a `mut`/`owned` parameter); never a temporary value, so a `mut` parameter has no default | read and `:set` |
| `owned x:T` | a value; moved (or copied if `Copy`) | anything, including move it on |

**Moving out of borrowed values.** A `read` or `mut` parameter of a non-`Copy` type, and a global, cannot be moved out of; pass or store a copy (`[$x->clone]`) instead.

**Exclusivity rule.** Within one call, a place passed as `mut` (including `mut self`) must not overlap any other argument's place. Two places overlap if one is a prefix of the other (`$a` and `$a->x`).

```pika
:fn push_twice mut xs:List<i64> v:i64 do={ $xs->push $v; $xs->push $v }

:local xs {1; 2}
:push_twice $xs 3            # ok
:swap $xs $xs                # error: `xs` is borrowed mutably and also borrowed
```

Small `Copy` arguments are passed by value; this is an optimization, not an observable difference.

**Destruction.** An owned value is destroyed at the end of the scope of the variable that owns it, unless it was moved out; a value moved on only some paths is destroyed exactly when it was not moved. A temporary is destroyed at the end of the statement that created it. `:set` destroys the old value before storing the new one. Globals are destroyed after `main` returns.

### 12.3 Heap allocation and sharing

- Collections and `String` own heap memory and free it when destroyed.
- `Box<T>` puts one value on the heap, mainly for recursive types:
  ```pika
  :enum Expr {
      num value:f64
      add left:Box<Expr> right:Box<Expr>
  }
  ```
  `[Box->new $value]` moves a value into a new box. `$b->value` is the value in the box, a place that can be read, borrowed and assigned with `:set ($b->value) ...`; it cannot be moved out of the box directly. `[$b->unbox]` takes the box and returns its value. A box is `Clone`, `Eq`, `Ord` and `Display` when its value is (comparing and displaying the value), and never `Copy`. A type may contain itself only through a box: `Box<Expr>` or `Box<Expr>?`, not `Expr?`.
- Shared ownership is provided by the standard library as `/std/rc/Rc<T>` (reference counted, single-threaded). Cycles of `Rc` leak; this is documented behavior, not a bug.

## 13. Modules, packages and FFI

### 13.1 Packages

A package is a directory with a `pika.toml` manifest:

```toml
[package]
name = "hello"
version = "0.1.0"

[dependencies]
# name = { path = "../other" }
```

Binary packages have `src/main.pk`; library packages have `src/lib.pk` (not both). Each `.pk` file under `src` is a module. The module `/hello/net/http` is the file `src/net/http.pk` in the package `hello`; the root module, `/hello`, is `src/main.pk` or `src/lib.pk`. A directory such as `src/net` is the module `/hello/net` even without a file `src/net.pk`.

- Package names and the names of module files and directories are identifiers (section 3.5).
- A dependency is a library package, named in `[dependencies]` by its own package name. A package can name itself and its direct dependencies in paths, not the dependencies of its dependencies. Dependencies cannot form a cycle.
- A program written as a single file is the root module of a binary package named `main`.
- Every package can also name the standard library's package, `std` (section 13.5), without declaring it. No other package can be named `std`.
- `pika run` and `pika check` take a `.pk` file or a package directory (the current directory by default).
- `pika build` makes a program into one executable that runs it with nothing else installed, named after the package or file unless `-o` names it; it takes the program's arguments, standard input and output, and exit status. The executable carries the program's sources and compiles them when it starts. (On macOS it runs where it is built, but is not a validly signed binary for distribution yet.)

### 13.2 Paths and imports

- Absolute paths start with `/` followed by a package name: `/std/math/sqrt`, `/hello/net/http/get`.
- `:use /std/math` makes `math` an alias, so `/math/sqrt` works.
- `:use /std/math/sqrt` imports the item, so it can be called as `:sqrt`. An item is a function, type, trait, constant or global; the import brings every item with that name.
- `:use /std/collections as=col` renames the alias or the imported item.
- The path of a `:use` starts with a package name, so `:use` declarations do not depend on each other's order. `:use` is written at the top level of a module.
- The first segment of any other path is resolved against `:use` aliases first, then package names. An alias cannot be the name of a package (other than the package it names), so a path never means two things.
- An imported name cannot clash with an item declared or imported in the module. Imports are not items: a module cannot be used to reach the items it imports.
- Paths are written wherever a name is: commands (`[/geo/area $s]`), values (`/geo/pi`), types (`p:/geo/Point`), literals (`/geo/Point{x=1.0; y=2.0}`), static members (`/geo/Color->red`, `[/geo/Point->new 1 2]`), patterns (`/geo/Color->red do={...}`), bounds and `impl=` lists (`<T: /geo/Shape>`).
- The prelude (`String`, `List`, `Map`, `Set`, `Option`, `Box`, `Duration`, `Error`, built-in traits and commands) is always in scope.

### 13.3 Visibility

Items, fields, methods and associated functions whose names start with `_` are private to the module that declares them. Everything else is public. There is no `pub` keyword.

- A private item cannot be named by a path or imported outside its module. A private field cannot be read, or given in a struct literal, outside the module of its struct; a private field with a default value can be left out, so such a struct can still be built elsewhere. A private method or associated function cannot be called outside its module.
- A module's submodules have no special access: privacy is per module.

### 13.4 Foreign functions

```pika
:extern lib="c" {
    :fn strlen s:Ptr<u8> -> u64
    :fn write fd:i32 buf:Ptr<u8> len:u64 -> i64
}

:unsafe {
    :const n [:strlen [$cstr->as_ptr]]
}
```

- `:extern` declares functions with the C ABI. Parameter and return types must be FFI-safe (integers, floats, `bool`, `Ptr<T>`, `nothing`, and structs declared `impl=CRepr`).
- Calling an extern function, dereferencing a `Ptr<T>`, and pointer arithmetic are only allowed inside `:unsafe { }`.

### 13.5 The standard library

The package `std` comes with the compiler. It is written in Pika, on top of a small set of operations that the runtime provides, and its modules are:

| Module | Contents |
|---|---|
| `/std/math` | constants (`pi`, `tau`, `e`, `phi`, `sqrt2`, `ln2`, `ln10`, `inf`, `nan`, `epsilon`, `max_float`, `min_positive`, `max_int`, `min_int`); float functions (roots, powers, exponentials and logarithms, trigonometric and hyperbolic functions, rounding, `copysign`, `mul_add`, `next_up`, `gamma`, `erf`, classification); `abs`, `sign`, `min`, `max` and `clamp` for any ordered numbers; integer functions (`gcd`, `lcm`, `isqrt`, `ilog`, `pow_int`, Euclidean division) and checked, wrapping and saturating arithmetic |
| `/std/math/bits` | counting, rotating and reordering the bits of `i64` values; powers of two |
| `/std/random` | `Random`, a seedable generator: integers in a range without bias, floats, `chance`, `shuffle`, `choice` |
| `/std/strings` | searching (`find`, `rfind`, `count`, `starts_with`), `slice`, splitting (`split`, `split_n`, `split_once`, `lines`, `words`), `join`, `replace`, trimming (white space or a set of characters), `strip_prefix`, padding, case conversion, `chars`, `bytes`, `reverse`; parsing and formatting integers in any base and floats with a precision |
| `/std/chars` | classifying characters (`is_whitespace`, `is_digit`, ...), case conversion, `to_digit`, `from_code` |
| `/std/collections` | sorting (stable, n log n, by order, comparison or key), binary search, `map`, `filter`, `fold`, `any`, `all`, `find_first`, `unique`, `dedup`, `chunks`, `windows`, `zip`, `flatten`, `slice`; map helpers (`get_or`, `frequencies`, `group_by`, `entries`); `Heap` (a priority queue) and `Deque` (a double-ended queue) |
| `/std/io` | `print` and `eprint` without a line break, `eput`, `read_line` |
| `/std/env` | the program's arguments (`args`) and environment variables (`var`) |
| `/std/time` | `monotonic` and `unix_time` clocks, `sleep` |
| `/std/fs` | `read`, `write`, `exists` and `remove` for whole files |

Positions in strings are byte offsets, as `:len` counts bytes; a position inside a character panics.

The standard library declares the operations of the runtime with `:extern lib="pika" { :fn sqrt x:f64 -> f64 }`. Only the standard library can use `lib="pika"`, and each declaration must match an operation of the runtime exactly; a declaration named with a leading `_` is private and declares the operation without the `_`.

## 14. Tests

```pika
:test "addition works" do={
    :assert ([:add 2 2] = 4) "2 + 2 should be 4"
}
```

A `:test` is a top-level declaration of any module: a name, which is a string without interpolation and unique in its module, and statements. `pika check` checks tests like functions; they are not part of the program that `pika run` runs.

- A test's statements run like the body of a function declared `raises`: an error that no `:onerror` catches fails the test, and so do panics, including a failed `:assert`.
- `pika test [path] [filter]` runs the tests of the package at `path` (or of a single file), not those of its dependencies, each in a process of its own so that a panic stops only its test. With `filter`, it runs the tests whose names contain it. A test outside the package's root module is named after its module's path in the package, as in `text/words: counts words`.
- It prints a line for each test, in declaration order, then the output and failure of each failed test, and a summary; it exits with status 0 if every test passed, and 1 otherwise. A test's output is shown only if it fails.
- `--interpret` runs the tests with the interpreter instead of compiling them.

```
running 2 tests
test adds ... ok
test text/words: counts words ... FAILED

failures:

---- text/words: counts words ----
--- stderr ---
panic: assertion failed: ([:count "one two"] = 3)
  left: 2
 right: 3
  at src/text/words.pk:4:5
the test panicked

test result: FAILED. 1 passed; 1 failed; 0 filtered out
```

## 16. Grammar summary (EBNF, informal)

```
file        := (item | stmt)* EOF
item        := use | fn | struct | enum | trait | impl | const | global | extern | test
impl        := ":impl" generics? type "{" fn* "}"                 (standard library only)
use         := ":use" path ("as=" IDENT)?
fn          := ":fn" IDENT generics? param* ("->" type)? "raises"? "do=" block
param       := ("mut" | "owned")? (IDENT | "self") (":" type)? ("=" atom)?
struct      := ":struct" IDENT generics? implList? "{" (field | fn)* "}"
enum        := ":enum" IDENT generics? implList? "{" (variant | fn)* "}"
variant     := IDENT (IDENT ":" type)*
trait       := ":trait" IDENT generics? implList? "{" fn_sig_or_fn* "}"   (generics: v1)
implList    := "impl=" path ("," path)*
field       := IDENT ":" type ("=" atom)?
generics    := "<" IDENT (":" bound)? ("," IDENT (":" bound)?)* ">"
bound       := path ("+" path)*

block       := "{" stmt* "}"
stmt        := (command | block) (";" | NEWLINE)
command     := head arg*
head        := (":" IDENT typeArgs? | path typeArgs? | IDENT typeArgs? "->" IDENT | "$" IDENT ("->" member)*
             | ("[" command "]" | "(" expr ")" | literal | collection) ("->" member)*) "?"?
arg         := IDENT "=" atom | atom
atom        := literal | var | path | IDENT typeArgs? "->" IDENT
             | "(" expr ")" | "[" command "]" | collection | IDENT typeArgs? structLit
var         := "$" IDENT ("->" member)*
member      := IDENT | INT | STRING | var | "(" expr ")"
collection  := "{" (elem (";" | NEWLINE))* "}"
elem        := atom | atom "=" atom
structLit   := "{" (IDENT "=" atom (";" | NEWLINE))* "}"
expr        := Pratt-parsed over atoms with the operators of section 7.1
path        := "/" IDENT ("/" IDENT)*
```

Control-flow commands (`:if`, `:while`, `:do`, `:for`, `:foreach`, `:match`, `:onerror`, `:unsafe`) have dedicated productions following section 8.

## 17. Implementation notes (non-normative)

The reference compiler is written in Rust.

```
source
  -> lexer            hand-written; tokens carry the "joined" flag; newline handling by bracket stack
  -> parser           recursive descent + Pratt; produces a lossless CST (for fmt and LSP)
  -> AST              typed view over the CST
  -> name resolution  modules, imports, scopes  -> HIR
  -> type checking    bidirectional inference, trait resolution; generic bodies are checked once
  -> MIR              control-flow graph, one body per function instance (monomorphization);
                      move/borrow checking on generic bodies, drop elaboration, `raises` lowering
  -> MIR interpreter  const evaluation
  -> codegen          Cranelift (v0); `pika run` compiles into memory (JIT); object files
                      for `pika build` and an LLVM backend come later
  -> link             system linker + small Rust runtime (allocation, panics, formatting, I/O)
```

Proposed workspace:

```
pika/
  Cargo.toml                 # workspace
  crates/
    pika_syntax/             # lexer, parser, CST/AST
    pika_hir/                # name resolution, HIR
    pika_types/              # type checker, trait solver
    pika_mir/                # MIR, borrow check, const eval
    pika_codegen/            # Cranelift backend
    pika_runtime/            # runtime library linked into programs
    pika_diagnostics/        # error reporting
    pika_driver/             # pipeline orchestration
    pika_cli/                # `pika` binary: new, build, run, test, fmt, check
  std/                       # standard library written in Pika
  tests/                     # conformance tests: .pk programs + expected output/errors
  docs/spec/
```

| Milestone | Scope |
|---|---|

## 18. Open questions

1. `:local` is mutable and `:const` immutable, to keep the `:local`/`:set` pairing. Should `:local` instead be immutable, with a separate mutable form?
2. Should calls that pass a `mut` argument be marked at the call site (for example `mut $xs`) for readability, or is the declaration enough?
3. Should `:put` and `:len` stay as built-in commands or become ordinary prelude functions that users could shadow?
4. Is `else=:if (...)` an acceptable "else if" form?
5. A `:match` on a variable borrows its parts, so it cannot take an owned value apart without passing it through a call (`:match [:pass $value]`). Should matching on an owned local (or an explicit move form) give its bindings ownership?
